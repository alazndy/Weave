# Turkish / English coverage: decisions and remaining work

Status: done on 2026-11-26.

## Decisions (user, 2026-11-26)
- App language (App settings) controls all interface text. No word of the other language may remain.
- Document language is a separate project setting (`ProjectMetadata.docLanguage`), saved in the project file.
  It controls title block, parts table, port cards, connector names, default sheet text, BOM CSV, PDF and PNG.
- Changes apply at once. User-typed text and edited title block headings are never translated.
- New project: document language = app language. Old project without the field: `tr`.

## Done
- Both locales are bundled from `src/locales/`. `documentT`, `appLanguage` in `src/i18n.ts`.
- `DocumentLanguageProvider` and `useDocumentT` in `src/i18nDocument.tsx` (not wired yet).

## Rules for new code
- Interface text: `t()` from `useTranslation`. Plain functions: `i18n.t()`.
- Text on a sheet or in an export: `useDocumentT()` or `documentT(language)`.
- Add each key to `src/locales/tr.json` and `src/locales/en.json`.
- `src/i18n.test.ts` fails on hardcoded JSX text, attributes, dialog texts and Turkish letters.
  It does not catch English strings inside expressions. `tests/e2e/22-language.spec.ts` checks the English
  interface for Turkish letters on the main screens only.
- Not translated: user data, trade names of connectors, document code lists in `src/data/documentCodes.ts` (English).
- `2026-11-26-i18n-inventory.txt` is the baseline before conversion.
